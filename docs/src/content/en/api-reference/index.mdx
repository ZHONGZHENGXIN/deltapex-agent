# 📚 API Reference Overview

Build AI Template provides a complete REST API that supports programmatic access to all core features. This documentation provides detailed API reference information.

## 🌐 API Basic Information

### Base URL

```
Production: https://your-domain.com/api/v1
Development: http://localhost:8000/api/v1
```

### API Version

Current API version: **v1**

We use URL path versioning to ensure backward compatibility.

### Content Type

All API requests and responses use JSON format:

```http
Content-Type: application/json
Accept: application/json
```

## 🔐 Authentication

Build AI Template uses JWT (JSON Web Token) for API authentication.

### Get Access Token

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "verification_code": "123456"
}
```

### Use Access Token

Include Bearer Token in request headers:

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

## 📊 Response Format

### Success Response

All successful API responses follow a unified format:

```json
{
  "success": true,
  "data": {
    // Response data
  },
  "message": "Operation successful",
  "timestamp": "2024-01-15T10:30:00Z"
}
```

### Error Response

Error responses contain detailed error information:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request parameter validation failed",
    "details": {
      "field": "email",
      "reason": "Invalid email format"
    }
  },
  "timestamp": "2024-01-15T10:30:00Z"
}
```

### Paginated Response

For list APIs, use unified pagination format:

```json
{
  "success": true,
  "data": {
    "items": [
      // Data item list
    ],
    "pagination": {
      "page": 1,
      "size": 20,
      "total": 100,
      "pages": 5
    }
  }
}
```

## 🚦 HTTP Status Codes

| Status Code | Meaning | Description |
|-------------|---------|-------------|
| 200 | OK | Request successful |
| 201 | Created | Resource created successfully |
| 400 | Bad Request | Request parameter error |
| 401 | Unauthorized | Unauthenticated or authentication failed |
| 403 | Forbidden | Insufficient permissions |
| 404 | Not Found | Resource not found |
| 422 | Unprocessable Entity | Data validation failed |
| 429 | Too Many Requests | Request rate limit exceeded |
| 500 | Internal Server Error | Server internal error |

## 🔄 Rate Limiting

To protect system stability, we implement rate limiting on API requests:

### Limit Rules

- **Regular Users**: 60 requests per minute
- **Premium Users**: 120 requests per minute
- **Administrators**: 300 requests per minute

### Rate Limit Headers

```http
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 59
X-RateLimit-Reset: 1642234800
```

### Rate Limit Exceeded Response

```json
{
  "success": false,
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "message": "Request rate limit exceeded, please try again later",
    "retry_after": 60
  }
}
```

## 🧪 API Testing

### Online API Documentation

Access interactive API documentation:

- **Swagger UI**: `http://localhost:8000/docs`
- **ReDoc**: `http://localhost:8000/redoc`

### Testing with cURL

```bash
# User login
curl -X POST "http://localhost:8000/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "verification_code": "123456"
  }'

# Get user information
curl -X GET "http://localhost:8000/api/v1/users/me" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

## 🔒 Security Best Practices

### API Key Security

- Don't hardcode API keys in client-side code
- Use environment variables to store sensitive information
- Regularly rotate API keys

### HTTPS Usage

- Production environment must use HTTPS
- Verify SSL certificates
- Use latest TLS version

### Input Validation

- Validate all input parameters
- Use parameterized queries to prevent injection attacks
- Limit request size and frequency
